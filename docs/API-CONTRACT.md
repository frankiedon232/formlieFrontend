# API Contract v0 (draft), Formalie

Shared by frontend (mocks) and backend (implementation). Bump the version and update this file on every change. Final contract is generated from FastAPI OpenAPI at hand-over.


> **Ids are encrypted references** (SECURITY-PROTOCOL §10): every `id` / `*_id` the API returns is a 27-character opaque reference, never a database id; send it back as it is. Raw ids are rejected.

## Conventions

- Base: `/api/v1`. All requests/responses use the encryption envelope (SECURITY-PROTOCOL.md); shapes below are the **decrypted** payloads.
- Auth: `Authorization: Bearer <fernet>`; `X-CSRF-Token` on POST/PUT/PATCH/DELETE; tenant from host.
- Success: `{ "success": true, "data": …, "meta": {…} }`
- Error: `{ "success": false, "error": { "code", "message", "trace_id", "details": [{ "field", "message" }] } }`
- Lists: query `page`, `page_size` (≤100), `q`, `sort` (`-updated_at`), `filter[status]=published`, `from`, `to` (ISO dates); meta `{ page, page_size, total, total_pages }`. Large sets: `cursor` instead of `page`, meta `{ next_cursor }`.
- **Paging happens in the database** (owner, 2026-10-04): a list request reads and sends only that page's rows (`LIMIT` / `OFFSET`, or keyset paging on indexed columns such as `submitted_at, id` for responses and audit), never the whole set; `total` comes from a separate `COUNT` (it may be an estimate above 100,000, then `meta.total_estimated: true`). Search, filters and sort run in the query on indexed columns (full-text index for searching answers). Insights and counts are aggregated in the database (`GROUP BY`), never by loading rows. The browser only ever holds one page. (The dev mock builds lists in memory and slices them; that is a stand-in only.)
- IDs are UUID strings; timestamps ISO-8601 UTC.
- Optimistic locking: editable resources return `row_version`; updates send it; mismatch → `FRM-GEN-1009`.

**`user`** (in tokens and `/me`): `{ id, first_name, last_name, email, avatar_url, role: owner|admin|member }`. `role` is the simple workspace role until Roles & access (F22); owner and admin manage the workspace (e.g. the audit trail).

**Refresh cookie:** `formalie_rt`, `HttpOnly; Secure; SameSite=Strict; Path=/api/v1/auth` (covers refresh + logout).
**Mock only:** challenge responses carry `meta.dev_code` so the dev code screen can show it; the real API never returns codes. The mock honours the dev header `X-Formalie-Dev-Tenant` (localhost / LAN-IP testing).

## Uploads

Files never pass through the enveloped API (SECURITY-PROTOCOL.md): the API hands out a pre-signed, expiring storage URL, the browser uploads straight to it (with progress), then confirms.

| Method | Path                     | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------ | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| POST   | `/uploads`               | `{ purpose, file_name, content_type, size }` → `UploadTicket { upload_id, upload_url, method: PUT, headers, max_bytes, expires_at }` (5 min). `logo` (admins): PNG / JPG / WebP ≤ 2 MB, SVG refused. `form_image` (any member, image blocks in forms): PNG / JPG / WebP / GIF / SVG ≤ 5 MB, bytes must match the type; SVG only as a plain drawing (no script, event handlers, `javascript:`, foreignObject, embeds) and served with a sandboxing CSP |
| PUT    | `upload_url`             | the raw file with the ticket's `headers`; storage checks size and that the bytes really are the declared image type                                                                                                                                                                                                                                                                                                                                    |
| POST   | `/uploads/{id}/complete` | → `UploadedFile { id, url, content_type, size }`; the id is what other endpoints take (e.g. onboarding branding `logo_upload_id`)                                                                                                                                                                                                                                                                                                                      |

**Mock only:** "storage" is `PUT /api/v1/storage/{token}` and files are served from `GET /api/v1/files/{id}` with `X-Content-Type-Options: nosniff`; production uses object storage + CDN URLs.

## Data sources (F12)

Admins only until Roles & access (F22). Settings are per engine (`shared/utils/datasources/engines.ts`: MySQL / MariaDB, PostgreSQL, SQL Server, Oracle); the same checks run on both sides (`checkConfig`). **Secrets are write-only**: passwords, client secrets, keys, passphrases and certificates are accepted on create / change, kept encrypted at rest, and never returned; replies only say which are set (`secrets_set`) and when they changed (`secrets_changed_at`). ## FormSchema (v1)

Field types: `shared/utils/forms/fields.ts` (text, dates, choice, rating, files, location, technical, advanced, layout, 47 types). Validated by `shared/utils/forms/schema.ts` (also used for imports). `props` per type: long text `rows`; currency `currency`; rating `max`; scale `min`, `max`, `min_label`, `max_label`; slider `min`, `max`, `step`; files `accept`, `max_files`, `max_mb`; matrix `rows[]` (columns = `options`); hidden / any field `prefill_param`; calculated `formula`; section `description`; paragraph `text`; image `src`, `alt`; full name `show_title`, `show_middle` (answer `{ title?, first, middle?, last }`); consent `text`, `link_label`, `link_href` (https only; answer `true`); duration answer `{ hours, minutes }`; ip address `ip_version` (`any` | `v4` | `v6`); language / time zone / currency answer the ISO code (BCP 47 language, IANA zone, ISO 4217); colour `#rrggbb`; percentage a number. Field access: `audience: { mode: everyone|department|role|user, all?, ids? }` (absent = everyone); a restricted field can't be `required` (publish check `locked_required`). `validation`: `min_length`, `max_length`, `min`, `max`, `pattern`, `pattern_message`, `min_selected`, `max_selected`.

```json
{

      "rows": [
        {

              "options": null,

              "default": null,

  "logic": [
    {
      "id": "rule_…",
      "when": { "all": [{ "field": "fld_a", "op": "eq", "value": "yes" }] },

  "calculations": [],
  "thank_you": { "title": "Thank you!", "message": "", "redirect_url": null }
}
```

Logic rules (`logic[]`): `when` holds **either** `all` or `any` (1–20 conditions) of `{ field, op, value?, value2? }`; `field` is a field id. Operators: text `eq neq contains not_contains starts_with ends_with`; numbers `eq neq gt gte lt lte between not_between` (`value` … `value2`); one choice `eq neq in not_in` (`value` = list); several choices `contains not_contains in contains_all count_gte count_lte`; yes / no `true false`; dates `eq before after between not_between` (ISO text); any field `empty not_empty`. Actions `then[] = { action, target?, value? }`: `show` (hidden until the rule matches) · `hide` · `show_page` / `hide_page` (target = page id) · `require` · `unrequire` · `enable` · `disable` · `set_value` (`value`) · `clear_value` · `jump` (target = page id, after the page holding the first condition's field; first match wins) · `skip_to_end` (no target). The server evaluates rules with the same semantics (`shared/utils/forms/logic.ts`): hidden fields and hidden pages are not validated, set values are applied before validation, and a field is **never required while it is hidden, read-only or disabled**.

Answer validation (`shared/utils/forms/validate.ts`, the server runs the same rules on submit and returns `FRM-GEN-1002` with one error per field key): required · email (`name@domain.tld`) · url (http/https with a host) · phone (6–15 digits, optional `+`, spaces / brackets / dashes allowed) · numbers (`validation.min` / `max`) · text length (`min_length` / `max_length`, rich text counts visible text) · `pattern` (+ `pattern_message`) · choices (`min_selected` / `max_selected`) · files (`props.max_files`) · date range (both dates, end ≥ start) · address parts: street (`line1`), city, country, postal code (unless `props.require_postal_code: false`), region (when `props.require_region: true`), also enforced when an optional address is partly filled in · full name (first + last) · consent (must be ticked when required) · duration (minutes 0–59, not zero) · IP address (IPv4 / IPv6 per `ip_version`) · domain · MAC (colon, dash or dot groups) · IBAN (ISO 7064 mod-97 checksum) · SWIFT / BIC (8 or 11 characters) · colour (`#rrggbb`) · language / time zone / currency (must be a known code). Codes: `ip`, `domain`, `mac`, `iban`, `bic`, `color`, `duration`, `name`, `consent`, `choice`.

Field properties: `readonly` (shown and submitted, can't be changed) and `disabled` (shown greyed out, **not** submitted), both mean "not required" (publish check `locked_required`). Options may carry a number, `options[].score`, used by formulas. Form setting `settings.label_position`: `top` (default) | `left` (beside the field where there is room; phones stack). Layout block props: section `{ description, size: lg|md|sm, divider: bool, align: start|center, collapsible, collapsed }` (an empty title shows only the line); paragraph `{ html }`, sanitised like rich text answers (older forms may still have plain `text`); divider `{ style: solid|dashed|dotted, spacing: sm|md|lg }`; image `{ src, upload_id?, alt, caption, size: 10–100 (% of the field), align: start|center|end|fill, height: auto|sm|md|lg (fill only, cropped like a banner), href (http/https only, opens in a new tab), rounded: bool }`. Section headings may carry `props.collapsible` / `props.collapsed` (display only). Rich text answers are **HTML** (`props.toolbar`: `full` (default) | `basic`), alignment can't be kept in Markdown. The server sanitises it with an allow-list (p, h1–h6, strong, em, u, s, code, pre, blockquote, ul, ol, li, a[href http/https/mailto], br; only `style="text-align: …"`) on submit and before showing it anywhere, and checks `validation.max_length` against the visible text. Upload fields keep allowed types in `props.accept` as an HTML accept list (`image/*,.pdf`); empty = any type; the server checks type and size again.

Calculated fields keep their formula in `props.formula`, a small safe language (`shared/utils/forms/formula.ts`, never `eval`): numbers, `{field_key}`, `+ - * /`, brackets, comparisons `= != > >= < <=`, `"text"` literals, functions `if(c, a, b) and or not min max sum round(x, digits) floor ceil abs`. A choice field counts as its chosen option's `score` (several chosen → their sum); compared with text it matches the option value or label. The server recomputes calculated values on submit and ignores posted ones.

Version list item (`GET /forms/{id}/versions`): `{ id, number, published_at, published_by: { id, name }, change_summary|null, fields_count }`; restore sets `has_unpublished_changes` to whether the restored schema differs from the live one.

Themes (`/themes`): `SavedTheme` = `{ id, name, tokens, source: system|saved|created, name_key?, forms_count, created_by, created_at, updated_at }`. `GET /themes?filter[source]=…` lists all three kinds (system = the starting points `sys_preset_*` and category designs `sys_category_*`, named through `name_key`); `GET /themes/{id}`; `POST /themes { name, tokens, source? }` (saved from a form, or created in the theme editor); `PATCH` / `DELETE` on system themes → `FRM-FORM-1014`; `POST /themes/{id}/duplicate { name? }` works for every kind (a system theme's copy is "created"). `GET /themes/insights` → `ThemeInsights` `{ by_source: {system, saved, created}, in_use, forms_total, forms_styled, top: {id, name, name_key?, forms}[] }` (the Themes page's totals for each card's share of forms; top = the three most used).

Page designs (`/page-designs`, owner 2026-10-04; shown to people as "Landing pages", decision 107): the page around a form on its public link, a library like Themes. `PageDesign` = `{ id, name, tokens { frame, page } (shared/utils/forms/page-design.ts), source: system|saved|created, name_key?, forms_count, created_by, created_at, updated_at }`. `GET /page-designs?filter[source]=…` (Formalie's ready-made designs `sys_page_*`, named through `name_key`), `GET /page-designs/insights` → `{ by_source, in_use, forms_total }`, `GET /page-designs/{id}`, `POST /page-designs { name, tokens, source? }`, `PATCH` / `DELETE` (system → `FRM-FORM-1014`), `POST /page-designs/{id}/duplicate { name? }`. A form applying one copies `frame` and `page` into its theme and keeps `schema.page_design_id`. Audit: `forms.page_design_created · updated · deleted`.

Theme tokens (`schema.theme`, and later `themes.tokens`), full shape in `shared/utils/forms/theme.ts` (`themeSchema`): `{ layout: card|plain|split|full, page: { bg_type: color|gradient|image, bg, bg_to, gradient_angle, bg_image, overlay }, container: { width, padding, radius, border, shadow, bg }, typography: { font: sans|system|serif|rounded|mono, size, heading_weight }, colors: { primary, text, muted, input_bg, input_border, error }, inputs: { radius, size, style: outline|soft|underline }, buttons: { radius, variant: solid|outline|soft, full_width }, header: { show_logo, logo, cover, cover_height, show_title, subtitle, align, band: none|color|gradient|accent, band_bg, band_to }, split: { image, side, panel: image|color|gradient, bg, bg_to }, footer: { enabled, text, links[{label, href https}], show_logo, align, style: plain|band, bg }, thank_you: { show_icon }, frame: { style: branded|spotlight|side|minimal, show_website, show_facts, tone: light|dark|brand } }`. Colours are `#rrggbb`; images are https URLs or `/api/v1/files/{id}`. A colour / gradient side panel carries the logo, title and intro (no header band then); a footer band is attached to the card in card / split layouts and full width otherwise; text on bands and panels is black or white for contrast. Tokens missing from older saved themes take the default. A missing or invalid group falls back to the workspace default (brand colour + logo); the public form endpoint returns the resolved theme.
