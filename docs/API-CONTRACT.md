# API Contract v0 (draft), Formalie

Shared by frontend (mocks) and backend (implementation). Bump the version and update this file on every change. Final contract is generated from FastAPI OpenAPI at hand-over.

> **Ids are encrypted references** (SECURITY-PROTOCOL §10): every `id` / `*_id` the API returns is a 27-character opaque reference, never a database id; send it back as it is. Raw ids are rejected.

## Conventions

- Base: `/api/v1`. All requests/responses use the encryption envelope (SECURITY-PROTOCOL.md); shapes below are the **decrypted** payloads.
- Auth: `Authorization: Bearer <fernet>`; `X-CSRF-Token` on POST/PUT/PATCH/DELETE; tenant from host.
- Success: `{ "success": true, "data": …, "meta": {…} }`
- Error: `{ "success": false, "error": { "code", "message", "trace_id", "details": [{ "field", "message" }] } }`
- Lists: query `page`, `page_size` (≤100), `q`, `sort` (`-updated_at`), `filter[status]=published`, `from`, `to` (ISO dates); meta `{ page, page_size, total, total_pages }`. Large sets: `cursor` instead of `page`, meta `{ next_cursor }`.
- **Paging happens in the database** (owner, 2026-10-04): a list request reads and sends only that page's rows (`LIMIT` / `OFFSET`, or keyset paging on indexed columns such as `submitted_at, id` for responses and audit), never the whole set; `total` comes from a separate `COUNT` (it may be an estimate above 100,000, then `meta.total_estimated: true`). Search, filters and sort run in the query on indexed columns (full-text index for searching answers). Insights and counts are aggregated in the database (`GROUP BY`), never by loading rows. The browser only ever holds one page. (The dev mock builds lists in memory and slices them; that is a stand-in only.)
- IDs are UUID strings; timestamps ISO-8601 UTC.
- Optimistic locking: editable resources return `row_version`; updates send it; mismatch → `FRM-GEN-1009`.

**`user`** (in tokens and `/me`): `{ id, first_name, last_name, email, avatar_url, role: owner|admin|member }`. `role` is the simple workspace role until Roles & access (F22); owner and admin manage the workspace (e.g. the audit trail).

**Mock only:** challenge responses carry `meta.dev_code` so the dev code screen can show it; the real API never returns codes. The mock honours the dev header `X-Formalie-Dev-Tenant` (localhost / LAN-IP testing).

## Uploads

Files never pass through the enveloped API (SECURITY-PROTOCOL.md): the API hands out a pre-signed, expiring storage URL, the browser uploads straight to it (with progress), then confirms.

| Method | Path                     | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------ | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| POST   | `/uploads`               | `{ purpose, file_name, content_type, size }` → `UploadTicket { upload_id, upload_url, method: PUT, headers, max_bytes, expires_at }` (5 min). `logo` (admins): PNG / JPG / WebP ≤ 2 MB, SVG refused. `form_image` (any member, image blocks in forms): PNG / JPG / WebP / GIF / SVG ≤ 5 MB, bytes must match the type; SVG only as a plain drawing (no script, event handlers, `javascript:`, foreignObject, embeds) and served with a sandboxing CSP |

**Mock only:** "storage" is `PUT /api/v1/storage/{token}` and files are served from `GET /api/v1/files/{id}` with `X-Content-Type-Options: nosniff`; production uses object storage + CDN URLs.

`POST /forms` takes `template_key` (system key or `ws_…`); the form remembers it (`template_key`) and `GET /forms?filter[template]=<key>` lists the forms made from a template; `GET /forms/facets` also returns `templates: [{ key, name }]` for that filter. A Formalie template's form (and `GET /templates/{key}?lang=`) comes in the requested `language` / `lang` when a translation exists: labels, options, help, page titles, consent / paragraph text, thank-you message and text results inside formulas, keys, option values, scores, logic and formulas stay the same; `settings.language` records it. Workspace templates are copied as written. Calculated fields may set `props.internal: true` (worked out and saved, not shown to respondents); formulas support `avg`, `count`, `days(from, to)` and text results. A formula may read a detail of the chosen list option as `{field.column}` (e.g. `{product.price} * {quantity}`; several chosen: their sum), and a logic condition may test one with `detail: "column"` (leftovers L1); the server works both out the same way as the form page.

Engine notes for the backend: identity columns (`GENERATED BY DEFAULT AS IDENTITY` on PostgreSQL and Oracle, `IDENTITY(1,1)` on SQL Server, `AUTO_INCREMENT` on MySQL / MariaDB); renames with `sp_rename` on SQL Server, `RENAME TABLE` on MySQL / MariaDB; column changes with `MODIFY` on MySQL / MariaDB / Oracle; SQL Server defaults are named constraints `DF_<table>_<column>` (the backend looks up the real name in `sys.default_constraints` before dropping one). **Never the whole table (backend rules, owner 2026-10-05).** The explorer reads one page at a time; nothing loads a whole table into memory, in the browser or on Formalie's servers.

1. **Paging in the database.** `rows` runs one query per page: `WHERE` for `q` and `filter[…]`, `ORDER BY` for `sort` (then the key, so pages are stable), and `LIMIT … OFFSET …` (MySQL, MariaDB, PostgreSQL) or `OFFSET … ROWS FETCH NEXT … ROWS ONLY` (SQL Server, Oracle). `page_size` is at most 100. Values are bound parameters, column names are checked against the table's columns and quoted the engine's way.
2. **A capped count.** The total counts at most 10,000 rows (`SELECT COUNT(*) FROM (SELECT 1 FROM … WHERE … LIMIT 10001)` or the engine's equivalent). Above that, `meta.total` is 10,000 with `meta.total_capped: true` and the list says "10,000+"; paging still works. "About N rows" comes from the database's own statistics, never a count.
3. **A time limit on every explorer statement** (5 seconds for rows, facets and the tree; exports run as jobs with their own limit): set per statement (`statement_timeout`, `MAX_EXECUTION_TIME`, `max_statement_time`, the driver's command timeout on SQL Server and Oracle), and cancelled when the browser leaves. A statement over the limit answers `FRM-DEST-1011`.
4. **Facets** come from a capped look (`GROUP BY … LIMIT 13` under the same time limit, or the database's statistics), never a scan without a limit; a column whose facet query runs over the limit simply gets no filter.
5. **The tree** reads only the catalogue (`information_schema` / `ALL_TAB_COLUMNS` / `sys.columns`), never table data.
6. **Exports** are this page by default, or up to 5,000 matching rows (`EXPORT_MAX_ROWS`), streamed into the file on Formalie's servers; the row panel's Previous / Next moves within the page that is loaded.
7. **Every request is checked against the signed-in person's workspace** (the connection, its table, the row); anything else answers "not found", the same as something that doesn't exist.

## FormSchema (v1)

Field types: `shared/utils/forms/fields.ts` (text, dates, choice, rating, files, location, technical, advanced, layout, 47 types). Validated by `shared/utils/forms/schema.ts` (also used for imports). `props` per type: long text `rows`; currency `currency`; rating `max`; scale `min`, `max`, `min_label`, `max_label`; slider `min`, `max`, `step`; files `accept`, `max_files`, `max_mb`; matrix `rows[]` (columns = `options`); hidden / any field `prefill_param`; calculated `formula`; section `description`; paragraph `text`; image `src`, `alt`; full name `show_title`, `show_middle` (answer `{ title?, first, middle?, last }`); consent `text`, `link_label`, `link_href` (https only; answer `true`); duration answer `{ hours, minutes }`; ip address `ip_version` (`any` | `v4` | `v6`); language / time zone / currency answer the ISO code (BCP 47 language, IANA zone, ISO 4217); colour `#rrggbb`; percentage a number. Field access: `audience: { mode: everyone|department|role|user, all?, ids? }` (absent = everyone); a restricted field can't be `required` (publish check `locked_required`). `validation`: `min_length`, `max_length`, `min`, `max`, `pattern`, `pattern_message`, `min_selected`, `max_selected`.

```json
{
  "schema_version": 1,
  "settings": { "progress_bar": true, "save_resume": false, "language": "en" },
  "pages": [
    {
      "id": "pg_…",
      "title": "Page 1",
      "rows": [
        {
          "id": "row_…",
          "fields": [
            {
              "id": "fld_…",
              "key": "full_name",
              "type": "short_text",
              "label": "Full name",
              "placeholder": "",
              "help": "",
              "width": 12,
              "required": true,
              "validation": {
                "min_length": 2,
                "max_length": 120,
                "pattern": null
              },
              "options": null,
              "option_set_id": null,
              "default": null,
              "props": {}
            }
          ]
        }
      ]
    }
  ],
  "logic": [
    {
      "id": "rule_…",
      "when": { "all": [{ "field": "fld_a", "op": "eq", "value": "yes" }] },
      "then": [{ "action": "show", "target": "fld_b" }]
    }
  ],
  "calculations": [],
  "thank_you": { "title": "Thank you!", "message": "", "redirect_url": null }
}
```

Logic rules (`logic[]`): `when` holds **either** `all` or `any` (1–20 conditions) of `{ field, op, value?, value2? }`; `field` is a field id. Operators: text `eq neq contains not_contains starts_with ends_with`; numbers `eq neq gt gte lt lte between not_between` (`value` … `value2`); one choice `eq neq in not_in` (`value` = list); several choices `contains not_contains in contains_all count_gte count_lte`; yes / no `true false`; dates `eq before after between not_between` (ISO text); any field `empty not_empty`. Actions `then[] = { action, target?, value? }`: `show` (hidden until the rule matches) · `hide` · `show_page` / `hide_page` (target = page id) · `require` · `unrequire` · `enable` · `disable` · `set_value` (`value`) · `clear_value` · `jump` (target = page id, after the page holding the first condition's field; first match wins) · `skip_to_end` (no target). The server evaluates rules with the same semantics (`shared/utils/forms/logic.ts`): hidden fields and hidden pages are not validated, set values are applied before validation, and a field is **never required while it is hidden, read-only or disabled**.

Answer validation (`shared/utils/forms/validate.ts`, the server runs the same rules on submit and returns `FRM-GEN-1002` with one error per field key): required · email (`name@domain.tld`) · url (http/https with a host) · phone (6–15 digits, optional `+`, spaces / brackets / dashes allowed) · numbers (`validation.min` / `max`) · text length (`min_length` / `max_length`, rich text counts visible text) · `pattern` (+ `pattern_message`) · choices (`min_selected` / `max_selected`) · files (`props.max_files`) · date range (both dates, end ≥ start) · address parts: street (`line1`), city, country, postal code (unless `props.require_postal_code: false`), region (when `props.require_region: true`), also enforced when an optional address is partly filled in · full name (first + last) · consent (must be ticked when required) · duration (minutes 0–59, not zero) · IP address (IPv4 / IPv6 per `ip_version`) · domain · MAC (colon, dash or dot groups) · IBAN (ISO 7064 mod-97 checksum) · SWIFT / BIC (8 or 11 characters) · colour (`#rrggbb`) · language / time zone / currency (must be a known code). Codes: `ip`, `domain`, `mac`, `iban`, `bic`, `color`, `duration`, `name`, `consent`, `choice`.

Field properties: `readonly` (shown and submitted, can't be changed) and `disabled` (shown greyed out, **not** submitted), both mean "not required" (publish check `locked_required`). Options may carry a number, `options[].score`, used by formulas. Form setting `settings.label_position`: `top` (default) | `left` (beside the field where there is room; phones stack). Layout block props: section `{ description, size: lg|md|sm, divider: bool, align: start|center, collapsible, collapsed }` (an empty title shows only the line); paragraph `{ html }`, sanitised like rich text answers (older forms may still have plain `text`); divider `{ style: solid|dashed|dotted, spacing: sm|md|lg }`; image `{ src, upload_id?, alt, caption, size: 10–100 (% of the field), align: start|center|end|fill, height: auto|sm|md|lg (fill only, cropped like a banner), href (http/https only, opens in a new tab), rounded: bool }`. Section headings may carry `props.collapsible` / `props.collapsed` (display only). Rich text answers are **HTML** (`props.toolbar`: `full` (default) | `basic`), alignment can't be kept in Markdown. The server sanitises it with an allow-list (p, h1–h6, strong, em, u, s, code, pre, blockquote, ul, ol, li, a[href http/https/mailto], br; only `style="text-align: …"`) on submit and before showing it anywhere, and checks `validation.max_length` against the visible text. Upload fields keep allowed types in `props.accept` as an HTML accept list (`image/*,.pdf`); empty = any type; the server checks type and size again.

Calculated fields keep their formula in `props.formula`, a small safe language (`shared/utils/forms/formula.ts`, never `eval`): numbers, `{field_key}`, `+ - * /`, brackets, comparisons `= != > >= < <=`, `"text"` literals, functions `if(c, a, b) and or not min max sum round(x, digits) floor ceil abs`. A choice field counts as its chosen option's `score` (several chosen → their sum); compared with text it matches the option value or label. The server recomputes calculated values on submit and ignores posted ones.

Version list item (`GET /forms/{id}/versions`): `{ id, number, published_at, published_by: { id, name }, change_summary|null, fields_count }`; restore sets `has_unpublished_changes` to whether the restored schema differs from the live one.

Themes (`/themes`): `SavedTheme` = `{ id, name, tokens, source: system|saved|created, name_key?, forms_count, created_by, created_at, updated_at }`. `GET /themes?filter[source]=…` lists all three kinds (system = the starting points `sys_preset_*` and category designs `sys_category_*`, named through `name_key`); `GET /themes/{id}`; `POST /themes { name, tokens, source? }` (saved from a form, or created in the theme editor); `PATCH` / `DELETE` on system themes → `FRM-FORM-1014`; `POST /themes/{id}/duplicate { name? }` works for every kind (a system theme's copy is "created"). `GET /themes/insights` → `ThemeInsights` `{ by_source: {system, saved, created}, in_use, forms_total, forms_styled, top: {id, name, name_key?, forms}[] }` (the Themes page's totals for each card's share of forms; top = the three most used).

Page designs (`/page-designs`, owner 2026-10-04; shown to people as "Landing pages", decision 107): the page around a form on its public link, a library like Themes. `PageDesign` = `{ id, name, tokens { frame, page } (shared/utils/forms/page-design.ts), source: system|saved|created, name_key?, forms_count, created_by, created_at, updated_at }`. `GET /page-designs?filter[source]=…` (Formalie's ready-made designs `sys_page_*`, named through `name_key`), `GET /page-designs/insights` → `{ by_source, in_use, forms_total }`, `GET /page-designs/{id}`, `POST /page-designs { name, tokens, source? }`, `PATCH` / `DELETE` (system → `FRM-FORM-1014`), `POST /page-designs/{id}/duplicate { name? }`. A form applying one copies `frame` and `page` into its theme and keeps `schema.page_design_id`. Audit: `forms.page_design_created · updated · deleted`.

Theme tokens (`schema.theme`, and later `themes.tokens`), full shape in `shared/utils/forms/theme.ts` (`themeSchema`): `{ layout: card|plain|split|full, page: { bg_type: color|gradient|image, bg, bg_to, gradient_angle, bg_image, overlay }, container: { width, padding, radius, border, shadow, bg }, typography: { font: sans|system|serif|rounded|mono|inter|roboto|open_sans|montserrat|poppins|dm_sans|work_sans|ibm_plex_sans|noto_sans|nunito|cairo|lora|merriweather|playfair|source_serif|noto_serif (web fonts self-hosted, `shared/utils/forms/fonts.ts`), size, heading_weight }, colors: { primary, text, muted, input_bg, input_border, error }, inputs: { radius, size, style: outline|soft|underline }, buttons: { radius, variant: solid|outline|soft, full_width }, header: { show_logo, logo, cover, cover_height, show_title, subtitle, align, band: none|color|gradient|accent, band_bg, band_to }, split: { image, side, panel: image|color|gradient, bg, bg_to }, footer: { enabled, text, links[{label, href https}], show_logo, align, style: plain|band, bg }, thank_you: { show_icon }, blocks: { section: plain|underline|accent|band, section_color: text|primary, section_caps, divider: line|accent|gradient|dots|space, divider_weight: thin|thick, paragraph: plain|muted|callout, image_radius: none|sm|md|lg|xl, image_shadow, image_border }, frame: { style: branded|spotlight|side|minimal, show_website, show_facts, tone: light|dark|brand } }`. `blocks` (owner 2026-10-08) styles sections, dividers, paragraphs and images; the default is today's look. `header.show_title` shows the form name under the organisation in the page frame (never in the form card). Colours are `#rrggbb`; images are https URLs or `/api/v1/files/{id}`. A colour / gradient side panel carries the logo, title and intro (no header band then); a footer band is attached to the card in card / split layouts and full width otherwise; text on bands and panels is black or white for contrast. Tokens missing from older saved themes take the default. A missing or invalid group falls back to the workspace default (brand colour + logo); the public form endpoint returns the resolved theme.

**API connections (F13, owner 2026-10-08).** `GET /api-service/connections?type=service|endpoint|token|rule&id=` → `ApiConnections { service, form, endpoints[{ id, name, status, service }], tokens[{ id, name, mode, status, reach }], rules[{ id, action, kind, values, enabled, reach }] }`, `reach` = `endpoint` (made for it) · `service` (for its service) · `all` (no service or endpoint chosen). **Choices by label in the public API (owner 2026-10-08).** Records (GET, and the record returned by POST / PUT) give a choice answer as its option label ("Footwear", or a list of labels for several choices), never the stored value code. POST, PUT and GET filters accept the label (any case) or the value; a label two options of one level share (a city name under two regions) is settled by the choice one level up. Examples follow the form's question order.

**Lists kept in the database (owner 2026-10-08).** Lists with more than 20 active options are treated like large lists below (no copy in forms, `options_large` on their fields, `level_counts` in the builder's list); lookup items may carry `attrs` (details for auto-fill).

**Long list lookup (F15 M3).** `GET /public/forms/{key}/options?field=&q=&values=&language=&channel=` (open forms, same access as the form page) → `{ items: [{ value, label }], total }`: up to 50 options of a long-list field (more than 300 options, no level above) whose label contains `q` (case and accents ignored, starting matches first), or the options for comma-separated `values`. ## Roles & access (F22, brought forward into F16)

Permissions (F22 R2, each with a scope `own · shared · own_shared · all` where it applies (shared = only forms others shared with them), on / off actions stored as `all`; catalogue in `shared/utils/auth/permissions.ts`): `forms.view|preview|create|import|duplicate|save_template|rename|edit|versions|share_view|share|availability|publish|close|archive|move|delete|purge` (scope own · shared · own_shared · all; create and import on / off), `folders.create|edit|delete|access` (edit and delete own · all), `templates.view|edit|duplicate|delete`, `lists|themes|pages.view|create|edit|duplicate|delete`, `data.view|create|edit|delete|browse|rows|structure|export|query|query_write|saved|storage` (edit and delete own · all; connections carry `can`), `api.view|service_create|service_edit|service_delete|endpoints|try|tokens|key|access|logs|webhooks` (service edit and delete own · all; services carry `can`), `ai.use|create|assist|analyse|translate|history|settings`, `fields.view|create|delete` (edit and delete own · all; template, list, theme, landing page and saved field rows carry `can { edit, delete }`; Formalie's items are never changed from a workspace; creating a template needs forms.save_template), `responses.view|review|edit|delete|export` (each own · shared · own_shared · all: responses to forms they made, forms shared with them, both, every form; FormSummary carries `responses_can`, `ResponseFormRow.can`, `ResponseDetail.can { review, edit, delete, export }`; review = status, tags, notes, possible-duplicate; edit = correct answers; `PATCH /responses/{id}` and `POST /responses/bulk` need review, with `data` also edit, bulk `delete` also delete; `POST /responses/{id}/files` needs view; `ResponseDetail.can { review, edit, delete }` combines the role and the person's access to the form), `analytics.view`, `people.view|manage|approve`, `roles.manage`, `settings.view|manage`, `audit.view|export` (`shared/utils/auth/permissions.ts`; some need others, e.g. edit needs view). Every signed-in call is checked against `permissionFor(method, path)`; a missing permission answers `403 FRM-PERM-1001`. `SessionUser` carries `role_name`, `permissions` and `grants` (each permission with its scope).

Forms (F22 R2): every `FormSummary` carries `can: { view, preview, duplicate, save_template, rename, edit, versions, share_view, share, availability, publish, close, archive, move, delete, purge }`, worked out from the role's scope, who made the form, whom it is shared with (people access) and its folder. `PATCH /forms/{id}` checks each change (name → rename, folder → move, dates → availability, tags → edit); lifecycle: unpublish · close · reopen → close, archive · unarchive → archive, restore → delete; `DELETE ?permanent=1` and `DELETE /forms/trash` → purge; bulk actions the same per form. Sessions carry `grants` next to `permissions`.

Folder access: `FormFolder` / `FolderRow` carry `created_by`, `can { edit, delete, access }` and `access { restricted, roles, departments, people }` (only for people with folders.access; others see `{ restricted }`). `PUT /folders/{id}/access` (folders.access) sets it; a restricted folder and its forms (and their responses) don't exist for people outside it (lists, counts, sidebar, search, responses, exports). Deleting a folder still needs it empty (`FRM-FORM-1013`, no count given).

People: `PersonRow.role` is a role id, with `role_name` and `privileged` (the role manages people, settings or roles); an unknown role → `422 FRM-USER-1009`.
